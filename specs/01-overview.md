# 運動会 リアルタイム得点管理・応援システム「SPO-CONNECT」仕様書概要

## 1. システム概要・全体アーキテクチャ

- **目的:** 自宅サーバー上で稼働し、モバイル回線環境（屋外、約100人接続想定）の運動会において、リアルタイム得点管理、キオスク端末による直感的なQRコード結果入力・名前変更、スマホを振る応援機能、および「写ルンです風」軽量カメラ機能を提供する。
- **インフラ & 永続化:**
  - **モノリス・コンテナ:** Node.js (Express + Socket.io) コンテナ内に SQLite3 を内蔵。
  - **データセット管理（DATABASE_ID）:** .env 内の `DATABASE_ID` は単なる切替スイッチではなく、データセットを選択する重要設定として扱う。使用可能な文字種（英数字およびハイフン等）を厳格に制限し、ファイルパスとして安全に処理する。
  - **データの正本とキャッシュの定義:**
    - **SQLiteの絶対的正本化:** システム内におけるすべてのデータ（ユーザー情報、スコア、状態）の正本（Source of Truth）は SQLite データベースのみとする。`user_cache.json` や `scores.json` などのJSONファイルは、すべて**「SQLiteからいつでも再生成可能な揮発性キャッシュ」**に限定する。
    - **更新順序とアトミック書き込み:** データの更新は必ず SQLite データベースのトランザクション完了（コミット成功）を前提とする。DBへの反映が正常終了した後に、対応するJSONキャッシュファイルを更新する。JSONファイルの書き換え時には、直接ファイルを上書きするのではなく、**同一ディレクトリ内に一時ファイル（.tmp）を作成して書き込んだ後、原子的なファイル置換（fs.rename）**を行い、書き込み途中の電源断やプロセス強制終了によるファイル破損を物理的に防止する。
    - **リビジョン管理と古さの検知:** キャッシュJSONには、生成時のシステムリビジョン番号およびタイムスタンプをメタデータとして含める。得点ボードやクライアント側はこれらを検証し、古いキャッシュや不整合データを検知した場合は即座に破棄して最新データを再取得する。
  - **起動時整合性チェックと安全停止:** 起動時、サーバーは指定された `DATABASE_ID` に対応するSQLiteファイルの存在、スキーマバージョン、およびDBファイル内部に記録された `db_id` の整合性を検証する。想定外の状態や不一致を検知した場合は、勝手に空のDBを新規作成して起動するようなことはせず、自動的に起動を停止してエラーログを出力する。
  - **操作の分離:** 「新規DB作成」「既存DBへの切替」「DB初期化（リセット）」は明確に別操作に分離し、初期化の実行には明示的な確認プロンプトとバックアップ作成を必須条件とする。
- **外部公開:** Cloudflare Tunnels を介して安全に外線公開。
- **ネットワークアクセス制御（ゼロトラスト・インフラ）:**
  - アプリケーションコンテナのポートはホストマシンへ直接公開（`ports` のバインド）せず、`expose` および内部ブリッジネットワーク（`internal_net`）を用いて、Cloudflare Tunnelコンテナからのみアクセス可能な閉じた構成とする。これにより、自宅LAN内からの不正なダイレクトアクセスやポートスキャンを物理的に遮断する。
- **機密情報（トークン）の管理方針:**
  - Cloudflare Tunnel の認証トークンやJWTシークレット等の機密情報は、コード内にハードコードせず `.env` ファイル（適切なパーミッション `600` の設定）で厳重に管理し、ホスト環境のセキュリティを担保する。

### 1.1 認証・認可モデル（RBAC）

外部公開環境（Cloudflare Tunnels）における無権限操作を防ぐため、サーバー側ですべてのREST APIエンドポイントおよびSocket.ioイベントに対してロールベースの認可を検証する。

- **ロール分類と許可スコープ:**
  - **管理者 (`ROLE_ADMIN`):** ホストアプリ専用。JSON生編集、得点の手動修正・Undo、得点マスク切替、キオスク端末用トークン発行、全ログ閲覧。
  - **キオスク：入場 (`ROLE_KIOSK_ENTRY`):** 入場QRのスキャンおよび1pt加算リクエスト（`reason: entry`）のみ許可。
  - **キオスク：順位 (`ROLE_KIOSK_RESULT`):** 順位モードのQRスキャン・リスト登録のみ許可。
  - **キオスク：ボーナス (`ROLE_KIOSK_BONUS`):** 競技ボーナスの付与のみ許可。
  - **キオスク：名前変更 (`ROLE_KIOSK_RENAME`):** ユーザー名の書き換えAPIのみ許可。
  - **一般参加者 (`ROLE_USER`):** 自身のQRコード表示、シェイクイベント送信、得点ボード（閲覧のみ）の同期。
- **認証メカニズム:**
  - 管理者は初期セットアップ時に設定されたパスワードを用いてログインし、JWT（管理者トークン）を取得する。
  - 各キオスク端末は起動時（または管理者による初期化時）、管理者が発行した「短時間有効なキオスク用トークン（Bearer Token / Socket handshake auth）」を保持して通信を行う。
  - キオスク端末ID（`kiosk-[文字列]`）は監査ログ用の識別子に過ぎず、認証・認可の根拠として利用してはならない。

### 1.2 Socket.io イベント分類とバックプレッシャー制御

100人規模の同時高頻度通信においてもサーバーのリソース（CPU・メモリ・DB I/O）を破綻させないため、イベントを以下の2種類に厳密に分類して負荷制御を行う。

- **高信頼性イベント (Guaranteed Events):**
  - **対象:** 順位確定、得点補償（Undo）、ユーザー名変更、特権操作コマンドなど。
  - **処理:** 即時DBトランザクション書き込み、ACK（到達確認）の返却、一意な `operation_id` による重複排除を行う。失われてはならないため、最優先で処理する。
- **流動ストリーミングイベント (Volatile / Throttled Events):**
  - **対象:** シェイク回数送信、リアルタイムランキング更新、得点ボードの表示状態同期など。
  - **レート制限（Rate Limiting）:** ユーザー単位でSocket送信頻度を制限（例: 最短200ms間隔）し、閾値を超える連続リクエストはサーバー側で破棄する。
  - **サーバー側インメモリ集約 (Batching):** 受信したシェイクデータは毎回DBに直接書き込まず、サーバーのインメモリバッファで集約する。指定間隔（例: 1秒〜2秒周期）でまとめてブロードキャスト（`io.emit`）し、集計完了時に一括してDB永続化を行う。
- **メモリ上限とリソース破棄 (Garbage Collection / Disconnect):**
  - Socket.ioの送信バッファ（キュー）に上限サイズを設定し、溢れた流動イベントは古いものから即座に破棄（Drop）する。
  - クライアント切断時（`disconnect`）には、該当ソケットに紐づくイベントリスナー、タイマー、およびバッファ領域を即座かつ確実に解放（Cleanup）し、メモリーリークを防止する。

```text
SPO-CONNECT/
├── .env.example
├── .gitignore

├── data/                               # Dockerボリューム（サーバー側永続化領域）

│   ├── cache/                          # user_cache.json 等の揮発性キャッシュ
│   ├── db/                             # SQLite3 データベースファイル
│   └── uploads/                        # 写ルンです風カメラの画像保存先 (7日間保持)
│
├── host-app/                           # ホスト用デスクトップアプリ (Tauri + React/Vue)
│   ├── package.json
│   ├── src-tauri/                      # Rust バックエンド
│   │   ├── Cargo.toml
│   │   ├── tauri.conf.json
│   │   └── src/
│   │       └── main.rs                 # OS Keychain 保持・Touch ID 連携・起動ロック
│   └── src/                            # ホストアプリのフロントエンド UI
│       ├── components/
│       │   ├── CheerPanel.jsx          # 応援集計パネル & ボーナス一括付与
│       │   ├── Dashboard.jsx           # リアルタイムステータス・競技フェーズ管理
│       │   ├── SyncModal.jsx           # オフライン差分同期・競合解決プロトコル UI
│       │   ├── UndoHistory.jsx         # 補償イベント型 Undo 履歴スタック UI
│       │   └── UserTable.jsx          # ユーザー・得点管理（明示的訂正モーダル付き）
│       └── utils/
│           ├── keychain.js             # OS セキュアストレージ連携
│           └── syncEngine.js           # 7段階ステートマシン同期 & アトミックJSON保存
│
├── public/                             # クライアント・キオスク用静的Web画面
│   ├── css/
│   │   └── style.css                   # レスポンシブ & チームカラー動的適用スタイル
│   ├── js/
│   │   ├── app.js                      # 参加者スマホ処理 (シェイク検知・属性再同期)
│   │   ├── camera.js                   # Canvas 写ルンです風加工 (1280px, モノクロ, Quality 0.7)
│   │   ├── outbox.js                   # キオスク送信待ちキュー & 分割/一括回収QR生成
│   │   ├── qr-scanner.min.js           # カメラQR読み取りライブラリ
│   │   └── socket.io.min.js
│   ├── index.html                      # 参加者スマホ画面 (QR表示・シェイク・カメラ)
│   ├── kiosk-board.html                # 得点ボード (演出マスク・カウントダウン対応)
│   ├── kiosk-bonus.html                # キオスク：ボーナス付与モード
│   ├── kiosk-entry.html                # キオスク：出席確認・受付モード (加算なし)
│   ├── kiosk-rename.html               # キオスク：ユーザー名変更モード
│   └── kiosk-result.html               # キオスク：順位結果入力モード (DRAFT/FINALIZED)
│
└── src/                                # サーバーサイド (Node.js / Express / Socket.io)
    ├── auth.js                         # JWT 発行・検証 & RBAC 認可ミドルウェア
    ├── config.js                       # .env バリデーション & 定数設定

    ├── migrations/                     # マイグレーションSQL群

    ├── routes/                         # REST API エンドポイント
    │   └── api.js                      # 出席、名前変更、写真アップロード(multer)、得点調整 API
    ├── scoring/                        # 競技別・配点計算エンジン
    │   ├── engine.js                   # 順位・同率配点算出処理
    │   └── rules.js                    # SAME_RANK_FULL / AVERAGE_SPLIT / CONTINUOUS_RANK
    ├── socket/                         # Socket.io リアルタイム通信 & バックプレッシャー制御
    │   ├── cheer.js                    # シェイク送信のレート制限 & 1~2秒周期インメモリバッファ集約

        └── hmac.js                     # QRコード・ペイロード改ざん防止 HMAC 署名検証
```
