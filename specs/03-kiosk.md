# 運動会 リアルタイム得点管理・応援システム「SPO-CONNECT」仕様書

## 4. キオスク端末仕様

### 4.1 出席確認・集計用モード (`kiosk-entry.html` / `kiosk-attendance.html`)

- **目的:** QRコードをスキャンすることで、ポイントの加算を行わずに**「誰が・いつ会場や受付に到着したか（出席確認）」**を記録・集計する専用モードとする。
- **ポイント付与の廃止:** 入場時の自動1ポイント付与仕様は一切行わない。これにより、QRコードのスクリーンショット共有や再利用による不正加算のリスクを構造的に排除する。
- **データベース記録:** スキャン時は `score_logs` ではなく、出席状況を管理する専用ログ（または `reason: 'attendance'` としてポイント加算値を 0 に設定した監査ログ）に記録し、ホストアプリのステータスビューで「現在の入場完了人数」をリアルタイムに把握するために使用する。

### 4.2 順位結果入力モード (`kiosk-result.html`)

- **入力状態の管理 (State Machine):**
  順位入力データは、以下のライフサイクルに従って厳密に状態管理される。
  - **DRAFT (編集中):** キオスク端末のメモリ（ローカル状態）上のみで保持されている状態。DBへの得点加算は行われない。
  - **FINALIZED (確定済み):** 確定ボタン押下により、一意な `operation_id` と共にサーバーへ送信され、DBへ正常に反映された状態。
  - **CANCELLED (打消済み):** 確定後の誤入力を訂正するため、明示的な取消イベントによってスコアログが無効化された状態。
- **編集（DRAFT）中の操作・トグル動作および連続検出防止（デバウンス）仕様:**
  - **連続検出防止プロトコル（Scan Debounce）:** カメラ読み取り成功後、**最低3秒間のクールダウン（デバウンス時間）**を設け、同一または別内容を問わずカメラ入力の受け付けを一時停止する。同一のQRコードについては、カメラの画角（フレーム）内から一定時間完全に外れたことが判定されるまで、再読み取り処理を実行しない。
  - **トグル解除と明示的なUI削除操作:** クールダウン経過後に同一順位で同じQRを再度スキャンした場合のみ、トグル解除（DRAFT リストからの除外）として処理する。トグル再スキャンだけに頼らず、キオスク画面上の「選択中ユーザーリスト」に**個別の「削除（×）ボタン」**を常設する。担当者は画面タップによって意図したユーザーだけを確実にリストから除外できる。
  - **端末ローカル状態の独立性:** DRAFT 状態（編集中リスト）は各キオスク端末のローカルメモリ上で独立して管理し、他端末での同時入力や通信リトライの影響を受けない。確定（FINALIZED）ボタンが押されて初めてサーバーへ一括コミットされる。
- **確定（FINALIZATION）およびUI確認フロー:**
  - **確定ボタンと確認モーダル:** 全順位の入力が完了した時点で「入力確定」ボタンを押す。確認ダイアログに「各順位の対象者一覧・付与ポイント・影響範囲」を一覧表示し、管理・担当者の明示的な承認を経てからサーバーへ一括送信（FINALIZED）する。
  - **送信と冪等性:** 各順位確定イベントにはクライアント側で生成した `operation_id` を付与し、サーバーDBへ一括コミットする。
- **確定（FINALIZED）後の訂正・取消フロー:**
  - 一度 FINALIZED となった順位結果を後から修正する場合は、単なるトグル解除ではなく、マイナス加算または対象 `operation_id` の無効化を行う「打消し（Cancel）イベント」をサーバーへ送信する。
  - 訂正履歴はすべて監査ログ（`score_logs`）に記録され、勝手なデータ消去を防ぐ。
- **重複登録制約ルール:**
  - **同一競技での複数順位制限:** 同一の「競技ID・ラウンド」において、1人の参加者が複数の順位（例: 1位と2位の両方）に DRAFT または FINALIZED 登録されることをデータベースおよびサーバーバリデーションレベルで拒否する。
- **配点ルールの選択・紐付け:**
  - 順位入力セッションの開始（またはホスト設定）時、該当競技に適用する 「同率順位の配点ルール（AllocRule）」 を選択する。
  - キオスク端末側は入力された「順位（1位、2位…）」と「対象者リスト」のみを送信し、具体的な得点計算はサーバー側の配点エンジンが選択されたルールに基づいて自動算出する。

### 4.3 ボーナスモード (`kiosk-bonus.html`)

- 順位モードとは独立した専用キオスク端末。特定の競技やパフォーマンスによる任意ポイントの付与を行う。

### 4.4 得点ボードモード (`kiosk-boad.html`) と演出マスク・秘匿仕様

- **機能の定義（演出特化の明確化）:** 本モードの得点非表示機能（マスク）は、あくまで会場のプロジェクターや参加者画面における**「結果発表前の演出用（ドラムロールやサスペンス感の演出）」**を目的としたものであり、通信傍受やクライアント解析に対する高度な情報秘匿（ゼロ知識証明や暗号化等）を保証するものではないことを仕様として明記する。
- **サーバー側でのデータ配信制御（セキュリティ強化）:**
  - ホストアプリから「得点非表示（`score:toggle_visibility`：LOCKED）」が有効化されている間、サーバーはスコアボード配信用Socket.ioイベントにおいて実際のポイント数データを一切配信しない。
  - 配信ペイロードには `"visibility": "hidden"` および演出用のプレースホルダー文字列（`"???"`, `"LOCKED"`）のみを含め、クライアントのネットワーク層に実得点が存在しない状態を作る。
- **公開（マスク解除）時のフロー:** ホストがマスク解除のスイッチを入れた瞬間、サーバー側で最新の集計結果を含む完全なスコアデータを一斉配信し、得点ボード側でカウントダウンや回転アニメーション等の演出を実行して確定値を描画する。
- **ホスト制御イベントと冪等性保証:**
  - トグル（反転）イベント `score:toggle_visibility` は通信リトライや重複受信で状態が逆転するリスクがあるため全面廃止する。
  - 代わりに、目標状態を直接指定する `score:set_visibility` イベント（ペイロード: `{ is_visible: boolean, version: number, operation_id: string }`）を採用する。これにより、通信遅延や重複受信が発生しても表示状態が揺らぐことはない。
- **バージョン管理と再接続同期:**
  - サーバーは得点表示状態のバージョン番号（`version`）を `system_state` テーブルで永続管理し、変更のたびにインクリメントする。
  - ネットワーク切断から再接続した得点ボード端末や、新規に起動した端末は、接続時の初期ハンドシェイク（または REST API）にてサーバーから最新の `is_visible` 状態と `version` を自動取得し、常に全端末間で同一の表示状態を維持する。

### 4.5 監査ログ & キオスク端末認証・認可仕様

- すべてのキオスク端末は、起動時に生成する `kiosk-[無作為の文字列]`（端末識別子）に加え、管理者が事前発行した各キオスク専用の認証トークン（JWT）をローカルストレージに保持する。
- サーバーへリクエストを送信する際、ヘッダー（またはSocket.ioの `auth` ペイロード）にトークンを添付する。
- サーバーは、要求された操作（例: 得点加算、名前変更）がトークンに割り当てられたスコープ（ロール）と一致しているかを必ず検証し、権限外の操作は即座に `403 Forbidden` を返して拒否する。
- セッション失効時や不審な通信を検知した場合、管理者はマスター画面から該当するキオスク用トークンをリモートで即座に失効（Revoke）させることができる設計とする。

### 4.6 競技別・配点計算エンジン仕様

順位入力（順位データ）と得点変換ロジック（配点データ）を完全に分離し、競技の特性や管理者の意図に応じて以下の配点アルゴリズムを自由に選択できる設計とする。

- **配点方式（Scoring Policy）の選択肢:**
  - **① 同一配点方式 (`SAME_RANK_FULL`):** 同率順位の全員に、該当順位の規定ポイントをそのまま全額付与する。
    - *例（規定：1位 10pt, 2位 7pt）:* 1位が3人いた場合、3人全員に 10pt を付与。次の「2位」には 7pt を付与。
  - **② 均等山分け（平均配点）方式 (`AVERAGE_SPLIT`):** 同率者の人数分だけ以降の順位枠を消費し、消費した順位枠の合計ポイントを同率者で均等に分配（小数点切り捨て等）する。
    - *例（規定：1位 10pt, 2位 7pt, 3位 5pt）:* 1位が2人いた場合、（10pt + 7pt）÷ 2 ＝ 8.5pt（端数処理指定） をそれぞれに付与。次の順位は 「3位（5pt）」 となる。
  - **③ スキップなし連続順位方式 (`CONTINUOUS_RANK`):** 同率者が何人いても、次の順位は常に「直後の数値順位（1位の次は2位）」とし、順位表通りのポイントを付与する。
- **配点ルール・バージョンの記録と再計算:**
  - データベースの `score_logs` には、計算に使用した `rule_id` および `rule_version` を記録する。
  - 競技途中でのルール変更や入力ミスによる再計算時も、どの配点ロジックに基づいて計算されたかが完全に追跡・再構築できる構造とする。
